# Skyrim Vertical Translation（SVT）

[English](README.md)

## 一个意外的项目

这个 mod 的开发过程有点曲折。大多数时候，我开发插件是因为自己有使用需求，但 SVT 完全是个意外。

实际上，我一直在开发一个改进 locomotion 的 mod，大概已经快四个月了。至于为什么会转到这个项目上，我自己已经完全忘了。

严格来说，SVT 并不是 AMR 的替代品，它没有实现 AMR 的功能。但实际上，它很可能会取代 AMR，因为 AMR 实现了一个游戏本来就有的功能：根运动。

## 原版中的三种根运动

游戏里居然存在三种不同的根运动方式：

1. **BGS 提取并单独存储的根运动数据。** BGS 将动画的根运动数据提取出来，存储在 `animationdatasinglefile.txt` 中。行为文件可以决定是否让特定动画使用这份数据。这条路径的数据单独存放，并不随附在动画本身。
2. **配对动画。** 行为文件可以决定是否让角色使用来自动画本身的根运动。这种情况下，动画携带自己的根运动数据。
3. **特定的龙类动画。**

我遍历了 `animationdatasinglefile.txt`，想找出原版到底哪些动画带有 Z 轴位移。答案是：只有极少数的龙类动画。

这些动画相当特殊。动画本身具有零净根位移：播放过程中可能有一些轻微的根位移，但最终会互相抵消。提取出来的根运动数据则以 `hkaDefaultAnimatedReferenceFrame` 的形式随附在动画中。

这正是 Havok 的标准做法：对原本携带根运动的 Havok Animation 执行 **Extract Motion**，再将提取出来的数据保留在动画里。

但为什么同一个动画需要两份数据？Havok 的这条路径真的有用吗？还是说，这只是没有被删除的残留数据？

经过大量的行为实验，我得出的结论是：龙类行为很可能是在 Havok 官方人员的协助下由 BGS 实现的。这是我根据实验作出的推测。游戏里仍保留着完整实现，任何生物都可以通过相同方式启用根运动，而且这条路径会优先于 BGS 的根运动方式。

## AMR 与 HCT

至于 AMR 为什么会出现，老实说，我并不清楚。从 2021 年到 AMR 出现的那段时间，我缺席了很久。

AMR 是一个介于 BGS 和 Havok 之间的混合方案。我猜，采用这条路线可能有两个原因：

1. alexsylex 很可能没有发现那些带有 ReferenceFrame 的动画，也就无从得知这条路径的存在。
2. Extract Motion 需要 HCT（Havok Content Tools）。这对动画作者来说可能很麻烦，而且分发 HCT 可能涉及版权问题。

更可行的办法，是做一个简单的 Blender 插件，或者类似的工具，来替代 Extract Motion 这一步。

## 迁移与速度问题

在市面上的动画都在使用 AMR 的情况下，迁移到 Havok 方案到底有没有必要，老实说我也不清楚。我只关心 1.5.97，AMR 后续的发展不在这个项目的考虑范围内。

对于 1.5.97，要替代 AMR，实际上只需要一个自动化工具，批量读取它的 annotation，并转换成等价的 ReferenceFrame 数据。另一种选择，是把原版 `animationdatasinglefile.txt` 中的数据转换成等价的 ReferenceFrame。

然后，把行为补丁中的 `bAllowRotation` 或 `bAnimationDriven` 换成 `bIsSynced`。不过，只有 BFCO、MCO 等少量 mod 需要这一步。

不过，我并没有做出这个批量转换工具。原版对 `animationdatasinglefile.txt` 和 ReferenceFrame 中相同数据的处理方式不太一样。即使动画和位移完全一致，最终为角色计算出的速度也可能不同。如果动画结束时留下了错误的速度，就可能触发行走或跑步动画。

根据我的观察，使用 BGS 方式时，角色在动画播放期间计算出的速度非常不稳定，会出现大幅跳动；使用 Havok 方式时，速度则非常稳定，几乎不会波动。

对原版数据进行机械转换后，我遇到了一个问题：动画结束时，速度会停留在一个较小的非零值，导致 locomotion 动画闪现一帧。

不过，在 AMR 到 Havok 的数据转换中，我没有发现这个问题。我最终没做这个转换工具，说到底还是因为懒。取代 AMR 并不是我的本意，而且这个插件本身根本就没有实现根运动。

## SVT 实际做了什么

**SVT 做的是防止原版阻止人类角色的 Z 轴根运动。** 这部分相当复杂，原版有大量限制来防止角色脱离地面。

我最初的想法，是找出龙类如何实现 Z 轴位移，再让人类照着做。但龙处于 `Flying` 状态，而这些限制只在 `OnGround` 状态下出现。

我猜，alexsylex 的思路也可能是寻找一种转换状态的方式来实现 Z 轴运动。alexsylex 也有一版支持 Z 轴的 AMR。

## `Flying` 状态的尝试

一开始，我尝试用 `Flying` 绕过这些限制。效果非常出色，代码量也极少，而且动画播放结束后，原版居然会自动处理状态转换。

问题在于，这个状态下没有正确的碰撞。

我为此进行了大量逆向，但始终没有找到想要的龙类 `Flying` 状态碰撞处理。我很确信它一定存在某种碰撞，最终找到的却主要是龙类主动避障的代码。

这里说的“真实飞行”，指的是原版的 `Flying` 状态。那些宣传“真实飞行而且带碰撞”的 mod，角色实际上并不处在这个状态下，而是使用了其他状态。

我还看了 Loki 的 Paraglider，因为印象里它有一个从平地起飞的功能。最后我的结论是，这些 mod 基本上都采用了某些巧妙的变通方式。

最终，我放弃了 `Flying` 这条路线。尽管实际效果很好，但我不想继续花大量时间弄清楚怎么给它补上正确的碰撞。

## 最后的实现

最后，我把自己折腾出来的那堆垃圾丢给了 AI，让它给我做了一个替代实现。

实际效果还不错。至少在我自己的审查中，没有发现什么问题。

也许未来我会重做这个 mod，但我的开发重心不在这里。

（而且，我根本就不使用那些带有 Z 轴根运动的 mod。）
